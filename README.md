# PTT 發文監控 — 使用說明

盯著 PTT **SportLottery** 板的指定帳號，只要他們一發新文章，你的手機就會跳通知，點通知直接開文章。

---

## 你只要做 3 件事，照順序點兩下就好

在桌機上打開這個資料夾，你會看到三個檔案，**照 1 → 2 → 3 的順序點兩下**：

| 點兩下這個 | 它會做什麼 | 大概要多久 |
|---|---|---|
| **1_安裝.bat** | 自動裝好程式需要的元件 | 1 分鐘 |
| **2_設定.bat** | 問你要追誰、教你設定手機 | 5 分鐘 |
| **3_開始監控.bat** | 開始跑，跑起來就不用管了 | 一直開著 |
| **4_查看今天.bat** | 隨時查「今天到現在」的完整清單 | 約 2 分鐘 |
| **5_更新雲端.bat** | 程式有更新時，一鍵傳到 GitHub 雲端 | 2 分鐘 |

前三個照 1 → 2 → 3 做完就一勞永逸。第 4 個是想查的時候才點。

每個都會跳出一個黑色視窗，照著上面的中文字做就好。

---

## 第 1 步：點兩下「1_安裝.bat」

黑色視窗會自己跑一陣子，最後出現「安裝完成！」就好了，按任意鍵關掉。

**如果它說「這台電腦還沒有裝 Python」**，那就要先裝 Python：

1. 用瀏覽器打開 <https://www.python.org/downloads/>
2. 按黃色那顆大按鈕 **Download Python**
3. 打開下載好的檔案，**安裝畫面最下面有一個小方框寫著 `Add Python to PATH`，一定要打勾**（這步沒勾的話後面會一直失敗）
4. 按 **Install Now**，等它跑完，按 Close
5. 回來重新點兩下「1_安裝.bat」

---

## 第 2 步：點兩下「2_設定.bat」

它會一步一步問你問題，你就打字回答、按 Enter。

**它會問「要監控哪些 PTT 帳號？」**
→ 打第一個帳號，按 Enter
→ 打第二個帳號，按 Enter
→ 沒有第三個了，**直接按 Enter** 就結束

> 帳號 ID 就是 PTT 文章列表左邊顯示的那個名字，例如 `kingfire`。大小寫不用管。

**接著它會給你一串亂碼一樣的字**，長得像 `ptt-xk3m9p2qw7vb4a`。

這串是你的專屬「頻道名稱」，**用手機拍下來，或抄在紙上**，等一下手機要用，不能打錯任何一個字。

### 然後拿起手機（Android）

1. 打開 **Google Play 商店**
2. 上面的搜尋框打 **`ntfy`**（就四個英文字母）
3. 找到一個**綠色擴音器圖示**、名字就叫 **ntfy** 的 App，按**安裝**
4. 裝好後按**開啟**
5. 畫面**右下角**有一個綠色圓形的 **「+」**，按下去
6. 會跳出一個輸入框（上面寫 Subscribe to topic），把剛剛那串字**一字不漏**打進去
7. 按下 **Subscribe**（訂閱）
8. 如果手機問你「要允許通知嗎」，選**允許**

弄好以後，回到電腦的黑色視窗，**按一下 Enter**。

**手機這時候應該會跳出一則通知，寫著「PTT 監控測試」。**

- ✅ **有跳出來** → 成功了，繼續第 3 步
- ❌ **沒跳出來** → 幾乎都是那串字打錯了。重新點兩下「2_設定.bat」，這次問你「要繼續用這個嗎」時打 **Y** 按 Enter（沿用同一串），然後仔細核對手機上打的字

---

## 第 3 步：點兩下「3_開始監控.bat」

會跳出一個黑色視窗，然後就**放著不要關**。

- 這個視窗**必須一直開著**，關掉就等於停止監控
- 可以把它縮到最小，不會影響你用電腦
- 每 3 分鐘它會自己去看一次 PTT，畫面會多一行字，那是正常的

**第一次跑的時候不會有通知**，因為它要先把那兩個帳號現有的文章都記下來當基準，不然你會被幾十篇舊文章洗版。從第二次檢查開始，只有真正的新文章才會通知你。

要停止的話，關掉那個黑色視窗就好。

---

## 第 4 步（想查的時候才用）：點兩下「4_查看今天.bat」

這個跟監控無關，是**隨時查「今天到現在為止」這些帳號做了什麼**。

點下去之後它會跑約 2 分鐘（畫面會顯示「已掃 30/89 篇」這種進度），跑完會**自動用瀏覽器打開一份報表**，長這樣：

```
PTT 動態報表
期間：08/03 · 看板：SportLottery

┌─ michael71230 ──────────────────────
│  發文 2
│    08/03 09:14  [推薦] 籃球 四場WNBA推薦
│    08/03 11:02  [LIVE] 排球 波蘭VS美國 場中
│  留言 65
│    08/03 10:22  推 公式想哭，只殺公式
│                 在 [LIVE] 阿甲 科爾多瓦學院 @ 拉努斯
│    08/03 10:25  推 讚
│                 在 Re: [LIVE] 阿甲 科爾多瓦學院
```

每一行的文章標題都可以點，直接連到 PTT。

想看更多天的話，這個要打指令：在資料夾空白處按 **Shift + 右鍵** → 「在這裡開啟 PowerShell 視窗」，然後打 `python today.py --days 3`（查最近 3 天）。

## 常見問題

**Q：我要換成追別的帳號怎麼辦？**
點兩下「2_設定.bat」重跑一次，重新輸入帳號。問你頻道要不要沿用時打 **Y**（沿用），這樣手機就不用重設。

**Q：桌機重開機以後還會繼續跑嗎？**
不會，要再點一次「3_開始監控.bat」。想要開機自動跑的話看下面「進階」。

**Q：我這台筆電和桌機可以都跑嗎？**
不行，會收到兩次重複的通知。**只留一台跑就好。**

**Q：通知會不會被別人看到？**
那串頻道名稱等於你的密碼，只要不給別人就沒事。所以千萬不要用好記的名字，程式幫你產生的亂碼是刻意的。

**Q：手機沒網路的時候發文了會漏掉嗎？**
不會，ntfy 會幫你留著，手機一連上網就補送。

## 進階（想弄再看，不弄也沒關係）

### 讓桌機開機就自動監控

1. 按 Windows 鍵，打「工作排程器」，打開它
2. 右邊點「建立工作」
3. **一般**分頁：名稱打「PTT監控」，勾選「不論使用者登入與否均執行」
4. **觸發程序**分頁 → 新增 → 「開始這項工作」選 **電腦啟動時** → 確定
5. **動作**分頁 → 新增：
   - 程式或指令碼：`python`
   - 新增引數：`ptt_watcher.py`
   - 開始位置：這個資料夾的完整路徑（例如 `C:\ptt-watcher`）
6. **設定**分頁：勾「如果工作失敗，每隔」，選 1 分鐘
7. 按確定

### 微調通知條件

用**記事本**打開 `config.json`（對著檔案按右鍵 → 開啟檔案 → 記事本），可以改：

| 你想要 | 把這行改成 |
|---|---|
| 檢查頻率（預設 60 秒一輪） | `"interval_seconds": 60` |
| 回文（Re:）不要通知我 | `"skip_reply": true` |
| 只有標題含「推薦」才通知 | `"title_include": ["推薦"]` |
| 通知強制響鈴（勿擾模式也響） | `"priority": 5` |
| 關掉留言通知，只留發文 | `"watch_comments": false` |
| 留言掃更久以前的文章（例如 24 小時） | `"comment_window_hours": 24` |
| 留言完整掃描更頻繁（例如 3 分鐘） | `"comment_interval_seconds": 180` |

改完存檔，然後把黑色視窗關掉再點一次「3_開始監控.bat」才會生效。

如果你的監控是跑在 **GitHub 雲端**上（電腦不用開機的那種），改完要點兩下「**5_更新雲端.bat**」，改動才會傳到雲端生效。

> ⚠️ 改的時候**不要動到雙引號、逗號和括號**，那些符號少一個程式就會壞掉。改壞了就重跑「2_設定.bat」。

## 給工程師看的技術細節

- 發文偵測的主要來源是**板面索引**（即時），從 `div.author` 直接比對作者。看板內作者搜尋 `https://www.ptt.cc/bbs/{board}/search?q=author:{id}` 只當備援——**搜尋的索引常常慢 30 分鐘以上**（實測：文章上了板面半小時後搜尋還查不到），不能當主要來源。PTT 沒有全站作者搜尋，所以一定要指定看板；要加板就往 `config.json` 的 `boards` 陣列加。
- 所有對 PTT 的請求都帶一個隨機的 `?_=` 參數防快取（PTT 回應標頭是 `max-age=900`，允許中途快取層留 15 分鐘的舊頁面）。
- **留言（推文）沒有任何搜尋 API**，只能列出看板索引 → 逐篇開文章 → 掃 `div.push`。所以留言監控的成本是發文監控的數十倍（發文 1 個請求 vs 留言數十個）。
  - 留言掃描分兩層：每一輪（跟著 `interval_seconds`，預設 60 秒）跑**快速掃描**；每隔 `comment_interval_seconds`（預設 180 秒）跑一次**完整掃描**，把時間範圍內每篇都重讀當保險網。
  - 程式碼裡有一個 `VERSION` 版本號，部署後第一輪會推「PTT 監控已更新」通知當部署確認（記在 `seen.json` 的 `version`，只發一次）。**改完程式記得把 `VERSION` 加一**，不然使用者收不到確認通知。
  - 快速掃描會重讀這幾種文章：推文數（`div.nrec`）有變動的、「爆」和「X1~XX」的、發文未滿 `comment_hot_hours`（預設 1）小時的、推文數空白且未滿 `comment_quiet_hours`（預設 3）小時的、以及**目標帳號留過言的**（LIVE 文他們會一直回來留言）。
  - 為什麼不能只靠 `nrec` 變動判斷：`nrec` 是推減噓的淨值，而板面顯示對噓文幾乎隱形——0～-9 分顯示空白、-10 起每 10 則噓才從 X1 變一次、-100 以下固定 XX、滿百固定「爆」，純箭頭（→）也完全不計。SportLottery 的 LIVE 文整串都在噓，所以這些「顯示不可信」的文章一律每輪直接重讀，剩下的極端漏網（噓在老文的隱形區）由完整掃描撿回，最壞延遲被 `comment_interval_seconds` 綁住。
  - 留言**找到就立刻推播**，不等整輪掃完（完整掃描一輪可能要幾分鐘）；每掃完一個板就先把 `seen.json` 存檔，中途被中斷也不會重複通知。
  - 推播失敗或文章讀取失敗時，會把該篇從 `nrec` 快取剔除，強迫下一輪重讀重試。
- 留言去重用 `md5(帳號|內容|IP時間)[:12]`，**不用「第幾則」**：中間有推文被刪時序號會整批位移，會造成大量重複通知。
- `recent_articles()` 往回翻頁的停止條件是「整頁都沒有落在時間範圍內的文章」，不能用「該頁最舊的一篇」——置底文永遠很舊，會害它第一頁就停手。
- 去重依據：文章 ID（`M.<unix_ts>.A.<hex>`），時間戳直接從 ID 取，排序穩定不依賴頁面順序。
- 狀態存在 `seen.json`；`baselined` 欄位獨立記錄哪些帳號已建立基準，不能用 `seen` 是否為空判斷（帳號在該板 0 篇文時會誤判）。
- 推播用 ntfy 的 JSON 端點（`POST https://ntfy.sh/` + `{"topic":...}`），不是 header 模式——header 帶中文會有編碼問題。
- 推播失敗的文章**不會**寫進 `seen.json`，下一輪自動補送。
- 連線內建 3 次退避重試（`urllib3.Retry`，backoff 1.5），PTT 偶爾會主動 RST。
- 環境變數 `PTT_AUTHORS` / `NTFY_TOPIC` / `NTFY_TOKEN` / `NTFY_SERVER` 可覆蓋設定檔，`.github/workflows/watch.yml` 是 GitHub Actions 版排程（cron 常延遲 5~15 分鐘，不建議當主力）。
